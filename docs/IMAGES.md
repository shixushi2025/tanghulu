# 图片获取与维护

## 本轮落地

63 条内容中，60 条已配图：全部 6 部电影、7 本书（含健康分类的两本）、31 个工具，以及其他可确认的产品、节目和作者条目。60 张图片全部转换为站内 WebP，当前展示不依赖外部图片服务。`src/data/images.json` 是实际展示清单，`docs/image-sources.json` 记录原图、发现页面、类型、版本、出处与权利说明。

3 条保留品牌占位图：睡眠记录是本站编辑练习，没有对应品牌封面；「快克大鱼」「随机波动」尚未确认准确节目资料，不随意拿同名图片代替。

书籍封面会标出「英文原版／英文版／中文电子版」等版本信息，避免把不同译本的封面混为一谈。《掌控习惯》使用 James Clear 官网封面。《纳瓦尔宝典》封面从官网公开 EPUB 的 OEBPS/image/cover.jpg 提取，《为什么我们要睡觉》使用出版社封面 CDN，《置身事内》使用豆瓣阅读对应电子版封面，《思考，快与慢》使用 Wikipedia 对应作品封面。电影按作品核对：5 张来自 Wikipedia 对应作品海报，千与千寻来自吉卜力作品页。

## 渠道研究与选择

| 类型／渠道 | 如何获得 | 优点与限制 | 本项目采用方式 |
| --- | --- | --- | --- |
| 工具官网 | 页面 icon / apple-touch-icon、品牌资源页 | 可核对身份；favicon 可能只有 16/32px，不能直接放大当高清图 | 优先取足够清晰的官方图标，人工查看 |
| Lobe Icons / Simple Icons | 明确品牌名称对应的图标 | 适合补官网访问受限的 Logo；不是全部商标的通用授权 | 少量补充，保留库许可证与品牌出处 |
| 作者／出版社 | 具体作品页、封面图片 | 更容易确认作品；同书不同语言、版本仍需区别 | 优先使用，对齐书名与版本 |
| Open Library Covers | ISBN / Cover ID / OLID | 可用 `default=false` 区分缺图与空白占位；公开页面要求直接用 Covers URL；ISBN 查询有限流 | 研究时验证了 4 个 ISBN，但当前浏览器环境的外部请求失败；最终换用其他来源，不用于当前展示 |
| Wikipedia / Wikimedia Commons | 对应作品页或具体文件页 | 非自由海报与开放许可照片是两回事，不能统称免版权 | 逐文件记录；Commons 照片展示作者、许可及转换说明 |
| TMDB API | 先匹配作品 ID，再取 poster_path，按 configuration 拼接图片尺寸 URL | 适合规模化影视库；需要 API 凭证并遵循使用与署名条款 | 作为后续批量渠道，本轮未配置账号、未虚构 API 接入 |
| 聚合 favicon 服务 | 用域名换图标 | 额外依赖、可能返回错误或低清图；读者访问会请求第三方 | 不作为本站默认方案 |
| 搜索引擎图片结果 | 搜索标题 | 容易混入同名作品、剧照、不同版本与无来源图片 | 只用于发现线索，不直接自动选第一张 |

研究依据：[Open Library Covers API](https://openlibrary.org/dev/docs/api/covers)、[TMDB 图片 URL 文档](https://developer.themoviedb.org/docs/image-basics)、[Simple Icons 说明](https://github.com/simple-icons/simple-icons/blob/develop/DISCLAIMER.md)、[Lobe Icons 文档](https://github.com/lobehub/lobe-icons)。

## 可靠性与性能

- 只从已审核清单同步，不在访问页面时临时抓取官网或调用搜索。
- 官方 EPUB 使用明确的 archiveMember 提取封面，仅将图片读入内存，不解压到站点目录。导入限制下载时间、重定向次数、文件大小与解码像素数；检查实际图像格式，拒绝含主动内容的 SVG；浏览器只收到转换后的 WebP。
- 站内图片使用内容哈希文件名，不重复加载未变化图片；通过 Cloudflare Pages 静态路由或 Workers Static Assets 提供，一年 immutable 缓存。
- Logo 保留留白，书封／海报完整显示，汽车相机图片完整显示，人物照片使用适合头像的裁切。
- 详情主图优先加载，普通列表图懒加载；容器预留比例及图片尺寸，避免布局跳动。
- 请求失败时显示原有品牌占位图；外部图片进入可视区域后超过 8 秒仍未加载，会取消图片请求并回退。默认不传 Referer。当前内置图片全部由本站提供；后台自填外部图片仍受外部可用性影响，失败不会阻止正文、导航或评分。
- 不额外引入在线图片代理和 API 密钥。

## 新增或更换图片

1. 在 `docs/image-sources.json` 添加明确的原图 URL、作品 ID、sourcePage、kind、edition、rights；需要署名的素材填写 credit、license、licenseUrl。对版本有疑问时先核对，不猜。
2. 运行 `npm run images:sync -- 条目ID`。不带 ID 会同步全部已审核来源。成功条目写入 `src/data/images.json` 与 `public/images/covers/`；失败保留已有可用图片，命令返回非零并写入报告。该命令不改数据库、不发布网站。
3. 看实际图片，确认没有同名误配、旧款产品、纯白图、低清图或大面积裁切。更新条目 Markdown 的 cover 为清单中的 src。
4. 创建新的增量迁移，只在旧 cover 匹配时更新。不要重写已经应用过的 `0007`；后台自定义封面应保留。
5. 运行 `npm run images:credits` 更新公开图片署名文件并检查许可副本，执行 `npm run verify`。图片来源清单、文件和内容必须一起提交。先发布图片资源，再执行 D1 路径迁移；保留仍被数据库引用的旧哈希文件，以便分阶段发布和回滚。

本轮 `0007_content_images.sql` 只填空封面，并检查标题、分类，避免给改成另一主题的条目错配图；保留后台封面、评分、浏览量，重复执行不产生变更。后台支持 HTTP(S) 图片 URL 和严格限定的 `/images/covers/*.webp` 站内路径。

## 权利与署名

公开可访问不等于开放许可。Logo 的商标权、书封和电影海报版权仍属于各自权利人，本项目仅在对应条目的介绍中使用识别性图片，不声称已获全部素材的商业授权。电影海报的 Wikipedia 非自由使用说明也不是对本站的自动授权。

富士 X100VI 照片：昼落ち，CC0 1.0。Model 3 照片：Alexander-93，CC BY-SA 4.0；缩小尺寸并转换 WebP，本地缩略图继续按同一许可提供，详情页显示作者及许可链接。图标库许可证副本在 `docs/licenses/`，公开资源署名在 `/images/ATTRIBUTION.txt`。

## 验证范围

离线测试核对图片文件、尺寸、体积、来源及缺图清单；数据库测试验证安全升级与重复执行。浏览器验证书封、海报、Logo 的实际解码和错误回退，并验证后台可保存站内封面。曾用本地浏览器检查 Open Library：当前环境返回 ERR_PROXY_CONNECTION_FAILED，因此改用了站内素材。CI 不依赖第三方图片在线状态。

## 渠道实测记录

- 官网部分 favicon 只有 32px；改用 SVG、高分辨率官方图标或维护中的图标库。
- 豆瓣图书图片 CDN 返回 418，但豆瓣阅读对应电子版作品页提供了可验证的封面，明确标注电子版。
- Open Library 通过服务端下载可验证图片，当前浏览器代理却无法连接；不把下载成功当作页面可用。
- Google Books 公共查询本次返回配额 429，未将其接入运行时。
- Wikimedia 的 X100VI 页面跳转到 X100 系列页，不能直接取其第一张旧型号图片；最终从明确标注 X100VI 的文件页选图。
